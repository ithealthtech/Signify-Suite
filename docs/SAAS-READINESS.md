`Complete` means the current implementation and automated evidence satisfy the
requirement. `Partial` means a working foundation exists but the production
target is not yet met. `Pending` means the named production capability has not
been implemented or accepted against a real sandbox service.

## Architectural Invariants

The modernization work must preserve these properties:

1. Application Owner authority is independent from tenant membership.
2. Every customer-owned record and operation is scoped to an organization.
3. Stripe remains an Application Owner control-plane integration.
4. Microsoft consent and directory data remain scoped to the consenting tenant.
5. Provider credentials are encrypted and never returned to browsers or logs.
6. Release artifacts contain no runtime database, customer media, backups, logs,
   or populated secrets.
7. Schema changes are forward-only, ordered, checksummed, and tested from a
   clean database before release.
8. UI success is shown only after durable backend completion.

## Verification Gate

No row may move to `Complete` solely because code compiles. Completion requires
the relevant unit, integration, security, migration, artifact, browser, provider,
or recovery evidence named in the final column.
